## 3. Reader lifetime is not the same as compiler lease lifetime

- The original `GetDBHandle` places a **mutable `QuestieStream` instance** inside a handle; query methods close over that stream. Passing `QuestieDB:Initialize()` and releasing all stream objects immediately is **not correct** while returned queries or older consumers retain references. Artificial misuse in [#274](https://github.com/CosmicCuddle/N-Questie/pull/274) and [#333](https://github.com/CosmicCuddle/N-Questie/pull/333) reproduces pool aliasing; it does not establish routine native corruption.
- Design a **generation residency ledger** separate from the compiler writer lease ledger: `PREPARING → VERIFIED → SELECTED → RETIRING → RECLAIMABLE` is a **proposed status vocabulary**, not an implemented state machine. Keep reference identity and reader closure ownership explicit; **RECLAIMABLE** is forbidden until all old consumers/callbacks/queued work are proven stopped or rebound and every associated stream is safe to return **exactly once**.
- An old generation retained until logout/reload may avoid use-after-recycle but can add **significant RAM**. Do not claim retention affordable; require WoW 3.3.5a heap, GC and frame measurement. If retirement cannot be proven, choose **no in-session hot swap** rather than force-return the pool or leak without bound.
- Whole `QuestieDB:Initialize()` cache reset alone does not prove Journey Search, tracker, Comms, queued callbacks and caller-retained handles reset together. [#317](https://github.com/CosmicCuddle/N-Questie/pull/317) explicitly contains a **constructed stale search result** across a naïve query-function rebinding.

## 4. Two mutually important atomicity scopes

**In one Lua scheduling interval:** a correctly ordered, no-yield **one-reference** selection of already validated, fully prepared generation plus matching reader-adapter state could provide a *cooperative in-memory logical transition*, **only** when all consumers use that adapter and retained old references are safe. It does **not** make eight independent legacy globals atomic if readers continue reading those fields.

**After logout/crash/relog:** WoW `SavedVariables` persistence is a separate serialization and file-recovery boundary. There is no demonstrated filesystem atomicity, durable flush acknowledgement or trusted two-slot journal in this addon. A checksum is not a trust/authentication proof (forged resealing witness in [#249–256](https://github.com/CosmicCuddle/N-Questie/pull/256)). Conservative selection must refuse invalid metadata/torn data and uncommitted spare fallback, then recompile or safely disable the cache when evidence is insufficient. It cannot promise no progress loss on a crash. **No automatic new-slot promotion without proven commit provenance.**

## 5. Explicit proposal for the first allowed implementation review

**Do NOT switch Stage1 yet.** Prepare a separate, **opt-in and uncalled** adapter design/draft with one output: a `SelectVerifiedCandidate(candidate, expectedMetadata)` **read-only** result describing a single eight-field candidate and its exact associated metadata, or a typed refusal. It must not mutate existing `Questie.db.global`, old eight fields, `QuestieDB.Query*`, stream pool, `hiddenQuests`, saved version/revision, or the current reader caches.

Before even this can be considered for integration:
1. independently identify its **real** `GetDBHandle` source/ABI/readback dependencies and pre-handle stream ownership, and refuse any handle acquisition when a candidate is not complete;
2. use an explicit returned `PASS/REFUSE` status, not log wording or a nonthrowing `Questie:Error`;
3. name an owner for its returned reader leases (including failure before a handle exists) without unsafe `pcall` across Lua5.1 yields;
4. demonstrate the existing direct-field legacy reader still behaves unchanged **when opt-in is disabled**;
5. reject stale revision, wrong locale/expansion, mismatched metadata or any `nil`/empty member in the full eight-field candidate;
6. keep all previous PR heads frozen; no install/ZIP/native tests/merge just because a test stub passes.

**Unresolved architectural choice:** typed candidate verification, even when implemented, is **not a cryptographic provenance guarantee** and **not** proof of writer exclusion or disk atomicity. Choosing actual source ownership/exclusion (I1), native memory limits (I7), and live reader migration (I4) must remain owner-reviewed decisions rather than being silently inferred from existing fixtures.
