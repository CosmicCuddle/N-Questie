## 4. Part48 findings, source evidence versus NATIVE UNKNOWN

### 4.1 Startup acceptance and tracker
- Historical original QuestieInit registers QuestEventHandler before QuestieCombatQueue.Initialize, with **seven coroutine yields** between. Yield count is **not** elapsed native time.
- QuestAccepted first writes an empty event-handler record, then queues HandleQuestAccepted. Original CombatQueue discards submission if private local started=false. **Conditional Case B**: if genuine QUEST_ACCEPTED arrives after event registration but before queue initialization, acceptance-specific HandleQuestAccepted may be lost; selective later UpdateAllQuests does not select a record that lacks state=QUEST_ACCEPTED.
- **Important correction:** startup QuestieQuest:GetAllQuestIds reconstructs cached quest records; QuestieTracker.Initialize separately schedules one-second delayed tracker synchronization. Therefore dropping an immediate prequeue tracker update is NOT proof of permanent empty UI. The delayed sync also does NOT replay acceptance-specific Journey timestamps/announcement or all HandleQuestAccepted effects.
- [#426 native observation matrix](../research/NQ-PART47-NATIVE-335-EVIDENCE-OBSERVATION-GATE.md) distinguishes **A** acceptance before registration, **B** registered/prequeue, **C** postqueue, plus actual event delivery, callback state, quest cache, Journey, optional announcements and tracker after-state. **A native B event and player-visible impact remain UNKNOWN.** Queue started is private local, so do not claim an external hook can read it; instrumentation needs separate permission. A single negative observation is inconclusive.
- Historical 3.3.5 FrameXML documents QUEST_ACCEPTED registration but cannot establish engine timing. Modern 8.0.1+ unknown-event registration exceptions are not evidence of a 3.3.5a startup crash.
