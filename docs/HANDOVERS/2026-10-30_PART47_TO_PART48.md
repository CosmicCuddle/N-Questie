## 6. Technical conclusions and critical boundary between source and native observations

1. **Genuine 335 event hook translation:** Original Compat posthook unregisters unsupported modern QUEST_TURNED_IN / QUEST_REMOVED events, uses reward/system-message and abandon hooks. Source-only deliberate fake AbandonQuest **without** captured SetAbandonQuest passes nil to genuine QuestRemoved even though fallback ID is computed; genuine private handler errors at nil table-index. **Actual 3.3.5a hook ordering/reachability and player impact UNKNOWN**. Not authorized to patch.
2. **Original timer:** The original 335 Compat animation timer clamps 0 delay to 0.01, runs repeating AnimationGroup callbacks, pools canceled animation timers, and has a distinct OnFinished handler vs user callback. Earlier red #405–#407 reflected **fake host callback property collision**, NOT genuine timer defect. Actual Blizzard timing/cadence UNKNOWN.
3. **Original CombatQueue:** Preinit submissions are dropped. Fake mid-drain combat lock defers remaining FIFO; reentrant Queue appends behind older work. With original maxUpdatesPerCircle=5 counter implementation, a fake cycle processes **six entries**, a source-level batch-count detail, NOT native player performance evidence.
4. **Two different completeness domains:** Historic 335 client GetQuestLogTitle isComplete typically **1 complete, -1 failed, nil otherwise**; client numeric 0 is noncanonical. Original DB QuestieDB.IsComplete maps **cached client nil with objectives present to addon-level numeric 0**. Genuine QuestieQuest.UpdateQuest uses that addon-internal value and clears WasComplete after a prior complete state. A supposed client 1→0 is NOT equivalent to addon internal 1→0.
5. **Objective normalized cache reuse:** For a fabricated client complete 1→nil with **unchanged raw objective** 0/2, whole original QuestLogCache retains already-forced normalized 2/2; original DB internal completion becomes 0. Genuine UpdateQuest can clear WasComplete and rebuild objectives from stale normalized complete values. **Only after another changed-quest update** may original all-objectives-complete fallback re-mark WasComplete while DB remains 0; invented raw progress change refreshes normalized incomplete status.
6. **Original event gate controls repetitions:** Under manually fabricated original event method calls, QUEST_LOG_UPDATE alone with no full-scan flag does not refresh; Watch+Log events can scan. Repeated identical events with no cache delta **do not** independently cause another UpdateQuest/re-mark WasComplete. A separate fabricated title change can force another update, but **real native 3.3.5a event ordering and client quest state sequence have NOT been reproduced**.
7. **Unresolved native evidence**: real QUEST_ACCEPTED arrival between source RegisterEvents and CombatQueue.Initialize during stage startup; true Blizzard AnimationGroup timing; whether AbandonQuest ever occurs without SetAbandonQuest; native quest flag 1→nil with stable raw objectives; actual WasComplete/quest objective player effects, original complete-addon behavior and AzerothCore/IP interaction.
